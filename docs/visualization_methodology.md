# Visualization Methodology: From Raw Data to Dashboard Charts

**Phase:** 6.6.2 — documentation only (no website changes)

---

## 1. Purpose

This document explains how each verified MC3 dashboard visualization was created, including:

- Raw data source and initial format
- ETL processing steps in `etl/automated_pipeline.py`
- Processed output files in `data/processed/`
- Verified website JSON exports in `website/data/verified/`
- JavaScript rendering logic
- Final chart and story use on the homepage

All metric values cited below come from current ETL outputs unless labeled **inferred**.

---

## 2. End-to-End Workflow

```
Raw CSV / Excel Source File
        ↓
Python ETL File Discovery (find_file_by_name / rglob)
        ↓
Pandas Loading and Cleaning (read_csv / read_excel)
        ↓
Column Standardization (clean_column_names → snake_case)
        ↓
Monroe County Filtering / Validation
        ↓
Processed CSV and JSON Outputs (data/processed/)
        ↓
Metric Validation Reports (metric_validation_report.json, phase6_indicator_validation_report.json)
        ↓
Verified Website JSON Exports (website/data/verified/)
        ↓
JavaScript Fetch (verified-data.js, verified-indicators.js)
        ↓
Chart.js Visualization (line charts)
        ↓
Plain-English Story Card (verified-indicators.js story fields + HTML placeholders)
```

| Step | What happens |
|------|----------------|
| **File discovery** | ETL searches `data/raw/` recursively for known filenames. |
| **Pandas load** | CSV or Excel loaded into a DataFrame. |
| **Column standardization** | Human-readable headers become snake_case. |
| **Filtering** | Monroe County rows kept via FIPS `18105`, county name, or STATSIN `cnty_fips == 105`. |
| **Type conversion** | Years → integer; rates/counts → numeric; missing coerced safely. |
| **Metadata** | `data_topic`, `indicator_name`, `source_file`, `etl_processed_at`, `verified` added. |
| **Outputs** | CSV + JSON written to `data/processed/`, then copied to `website/data/verified/`. |
| **Validation** | ETL compares poverty metrics to `dashboard_summary.json`; Phase 6 report flags graduation/unemployment mismatches. |
| **Frontend fetch** | Static `fetch()` loads JSON from `data/verified/`. |
| **Chart.js** | Line charts plot `year` on x-axis and metric value on y-axis. |
| **Story cards** | Latest values from JSON; explanatory text from JS config. |

---

## 3. Project-Level Data Flow

| Location | Role |
|----------|------|
| `data/raw/` | Copied source CSV/XLSX files (read-only copies of originals) |
| `data/processed/` | ETL-cleaned CSV/JSON and validation reports |
| `website/data/verified/` | Website-ready verified JSON (exported by ETL) |
| `website/data/processed/` | **Original dashboard JSON — preserved, not overwritten** |
| `database/schema/`, `database/views/` | Optional PostgreSQL structures; static site does not require DB |

Verified JSON is **generated by** `python automated_pipeline.py` on each run.

## 4. Child Poverty Trend

### Final Website Use

- Verified indicator **card** (`card-poverty-value`)
- **Mini trend chart** (`verifiedPovertyMiniChart`)
- **Detailed trend chart** (`verifiedPovertyChart`)
- Story text on card (via `verified-indicators.js`)

### Question Answered

How has Monroe County's verified child poverty rate changed over time?

### Raw Data Used

| Field | Value |
|-------|-------|
| **Path** | `data/raw/misc/dataset_archive/Children in Poverty.csv` |
| **Type** | CSV |
| **Original columns** | `County ID`, `County`, `Year`, `Children In Poverty`, `Children In Poverty CI High`, `Children In Poverty CI Low` |
| **Row count** | 11 data rows (Monroe County only in cleaned output) |
| **Year range** | 2014–2024 |
| **Representation** | Child poverty rate as a **proportion** (0–1) with confidence interval bounds |

### Initial Form of the Data

- CSV with spaced, title-case column names
- One row per county-year; this file contains Monroe County only
- `Children In Poverty` stored as decimal proportion (e.g. `0.202` = 20.2%)
- Confidence interval high/low columns included but not plotted on homepage charts

### Processing Steps

1. `find_file_by_name("Children in Poverty.csv")` under `data/raw/`
2. `pd.read_csv(source_path)`
3. `validate_required_columns()` against `REQUIRED_POVERTY_COLUMNS`
4. `clean_column_names()` → `county_id`, `county`, `year`, `children_in_poverty`, etc.
5. Convert `year`, `children_in_poverty`, CI columns to numeric
6. Extract `county_fips` from `county_id` (last 5 digits → `18105`)
7. Filter: `county_fips == "18105"` OR county name contains `"Monroe County"`
8. Compute `children_in_poverty_rate_pct = children_in_poverty * 100`, rounded to 1 decimal
9. Add metadata: `data_topic=demographics`, `indicator_name=children_in_poverty`, `value_type=rate_proportion`, `verified=True`
10. `calculate_poverty_metrics()` → `poverty_metrics_verified.json`
11. `compare_existing_dashboard_metrics()` → `metric_validation_report.json`
12. Save `children_in_poverty_clean.csv/json`; export to `website/data/verified/`

**Function:** `clean_children_in_poverty()` in `etl/automated_pipeline.py`

### Processed Data Created

- `data/processed/children_in_poverty_clean.csv` (11 rows)
- `data/processed/children_in_poverty_clean.json`
- `data/processed/poverty_metrics_verified.json`
- `data/processed/metric_validation_report.json`
- `website/data/verified/children_in_poverty_clean.json`
- `website/data/verified/poverty_metrics_verified.json`
- `website/data/verified/metric_validation_report.json`

### Fields Used in the Chart

| Role | Field |
|------|-------|
| x-axis | `year` |
| y-axis (mini + detailed) | `children_in_poverty_rate_pct` |
| Fallback y-axis | `children_in_poverty` × 100 (detailed chart only) |
| Latest value | `end_value_pct` from `poverty_metrics_verified.json` → **14.0%** |
| Latest year | `end_year` → **2024** |
| Unit | percent |
| Source | `source_file` |
| Trend summary | `percentage_point_change` → **6.2**; `percent_change_relative` → **-30.69%** |

### Metric Calculation

From `calculate_poverty_metrics()`:

- `start_value_pct` = first year proportion × 100 → **20.2%** (2014)
- `end_value_pct` = last year proportion × 100 → **14.0%** (2024)
- `percentage_point_change` = `start_value_pct - end_value_pct` → **6.2**
- `percent_change_relative` = `((end - start) / start) × 100` → **-30.69%**

### JavaScript Rendering

| Item | Detail |
|------|--------|
| **Mini chart** | `website/js/verified-indicators.js` → `renderMiniChart()` |
| **Canvas ID** | `verifiedPovertyMiniChart` |
| **Detailed chart** | `website/js/verified-poverty-chart.js` → `renderVerifiedPovertyChart()` |
| **Canvas ID** | `verifiedPovertyChart` |
| **Data loader** | `website/js/verified-data.js` → `loadVerifiedPovertyTrend()`, `loadVerifiedPovertyMetrics()` |
| **Chart type** | Line (`Chart.js`) |
| **Init** | `initVerifiedCommunityIndicators()` and `initVerifiedPovertySection()` on `DOMContentLoaded` |
| **Missing data** | Console warning; fallback text on detailed chart; card shows "Data unavailable" |

### Storytelling Interpretation

Child poverty is one measure of economic pressure surrounding families. The verified trend shows improvement from 20.2% to 14.0%, but the 2024 rate still indicates many families may need support.

### Validation and Limitations

- **Verified:** 6.2 percentage-point decrease (2014–2024)
- **Flagged:** `dashboard_summary.json` claims **8.3pp** — shown in `metric_validation_report.json` and detailed section warning box
- **Limitation:** Trend does not explain cause; CI columns exist in data but are not charted

## 5. Graduation Rate Trend

### Final Website Use

- Verified indicator **card**
- **Mini trend chart** (`verifiedGraduationMiniChart`)
- Story text on card

### Question Answered

What was Monroe County's verified high school graduation rate over the years available in the source file?

### Raw Data Used

| Field | Value |
|-------|-------|
| **Path** | `data/raw/education/reference_repo/High school graduation rate.xlsx` |
| **Type** | Excel (Kids Count export) |
| **Sheet** | `Kidscount Export` |
| **Required columns** | `location`, `timeframe`, `dataformat`, `data` |
| **Row count** | 12 rows after filtering (2006–2017) |
| **Year range** | 2006–2017 |
| **Representation** | Graduation rate; `dataformat = "Percent"` |

### Initial Form of the Data

- Excel Kids Count export with human-readable column names
- Multiple locations and formats; ETL keeps `location == "Monroe"` and `dataformat == "Percent"`
- `data` values stored as proportions (e.g. `0.9077`) before ETL multiplies by 100

### Processing Steps

1. `_load_kidscount_monroe("High school graduation rate.xlsx", data_format="Percent")`
2. `pd.read_excel(..., sheet_name="Kidscount Export")`
3. `clean_column_names()` on columns
4. Filter Monroe + Percent rows
5. `year` ← `timeframe` (integer); `indicator_value` ← `data` (numeric)
6. `indicator_value = indicator_value * 100`, rounded to 2 decimals
7. `_add_lineage_fields()` → `indicator_name=high_school_graduation_rate`, `value_type=rate_percent`
8. Save `graduation_rate_clean.csv/json`; export to `website/data/verified/`

**Function:** `clean_graduation_rate()`

### Processed Data Created

- `data/processed/graduation_rate_clean.csv` (12 rows)
- `data/processed/graduation_rate_clean.json`
- `website/data/verified/graduation_rate_clean.json`

### Fields Used in the Chart

| Role | Field |
|------|-------|
| x-axis | `year` |
| y-axis | `indicator_value` |
| Latest value | **90.77%** (2017) |
| Unit | `indicator_unit` = `percent` |
| Source | `source_file` |

### Metric Calculation

Latest value = last row after sort by `year` → **90.77** in **2017**.

Mini-chart trend label (non-poverty): computed first-to-last change in `buildTrendLabel()` when no static `trendLabel` set.

### JavaScript Rendering

| Item | Detail |
|------|--------|
| **File** | `website/js/verified-indicators.js` |
| **Config ID** | `graduation` |
| **Canvas** | `verifiedGraduationMiniChart` |
| **Value field** | `indicator_value` |
| **Filter** | `indicator_name === "high_school_graduation_rate"` |
| **Format** | `toFixed(2)` + `%` |

### Storytelling Interpretation

Graduation reflects one part of the learning environment. The verified source ends in 2017, so it describes educational opportunity for that period only.

### Validation and Limitations

- **Verified latest:** 90.77% in 2017
- **Flagged:** Dashboard **95%** claim in `phase6_indicator_validation_report.json`
- **Limitation:** Source ends 2017; do not use newer graduation claims until re-verified

- Verified indicator **card**
- **Mini trend chart** (`verifiedUnemploymentMiniChart`)
- Story text on card

### Question Answered

What are Monroe County's verified county unemployment rates in the available STATSIN files?

### Raw Data Used

| Field | Value |
|-------|-------|
| **Paths** | `data/raw/economy/reference_repo/Unemployment_Estimates/STATSIN_asu20.xlsx` through `STATSIN_asu25.xlsx` |
| **Type** | Excel |
| **Sheet** | `data` |
| **Key columns** | `cnty_fips`, `cnty_urate` (after `clean_column_names`) |
| **Row count** | 6 rows (2020–2025) |
| **Year range** | 2020–2025 |
| **Representation** | County unemployment rate (percent) |

### Initial Form of the Data

- One file per year; year inferred from filename suffix (`asu25` → 2025)
- STATSIN uses `cnty_fips = 105` for Monroe County within Indiana
- `cnty_urate` is already on percent scale (e.g. `5.8`)

### Processing Steps

1. `rglob("STATSIN_asu*.xlsx")` under unemployment estimates folder
2. Parse year from filename: `2000 + int(asuYY)`
3. `pd.read_excel(path, sheet_name="data")`; `clean_column_names()`
4. Filter `cnty_fips == 105`
5. `indicator_value = round(cnty_urate, 1)`
6. Combine all years; sort; `_add_lineage_fields()` with semicolon-joined `source_file`
7. Save `unemployment_rate_clean.csv/json`; export to website

**Function:** `clean_unemployment_rate()`

### Processed Data Created

- `data/processed/unemployment_rate_clean.json`

| Latest value | **5.8%** (2025) |
| Unit | `percent` |
| Source | `source_file` (multiple STATSIN paths) |

### Metric Calculation

Latest row after sort → year **2025**, value **5.8**.

### JavaScript Rendering

## 9. Verified Indicator Cards

### Final Website Use

Five **story cards** in `#verified-indicators-dashboard` — one per indicator.

### Question Answered

What is the latest verified value for each community indicator, and what does it mean in context?

### Data Source

Each card loads its indicator file from `website/data/verified/` via `VERIFIED_INDICATOR_CONFIG` in `verified-indicators.js`.

### Card Content Model

| Element | Source |
|---------|--------|
| Metric value + year | JSON (`children_in_poverty_rate_pct` or `indicator_value` + `year`) |
| Trend label | `poverty_metrics_verified.json` or `buildTrendLabel()` |
| Story connection | Hardcoded explanatory text in JS config |
| Why it matters | Hardcoded in JS config |
| Source note | `source_file` from latest JSON row |
| Limitation | Hardcoded in JS config |

### JavaScript Rendering

- **File:** `website/js/verified-indicators.js`
- **Entry:** `initVerifiedCommunityIndicators()` on `DOMContentLoaded`
- **Functions:** `updateCard()`, `populateStoryFields()`, `renderMiniChart()`
- **Missing file:** `console.warn`; panel gets `verified-indicator-missing` class; value shows "Data unavailable"

### Validation and Limitations

- Metric values always from ETL JSON — never hardcoded in JS
- Story text is explanatory, not a second data source
- `phase6_indicator_validation_report.json` populates `#verified-multi-warning` when warnings exist
